# Isle of Souls PvP zones

Player-versus-player combat is allowed only inside zones the event settings open. Everywhere else the
game is as before (no Attack option on players). Deaths stay safe everywhere: `PlayerDeath` drops
nothing, and a dead player respawns at the Soul Wars lobby graveyards.

## Event settings

`.data/league/event-settings.json`, read once at startup (a change needs a restart):

```json
"pvp": {
  "soulWarsArena": true,
  "revenantCaves": true,
  "wildernessBossLairs": true,
  "escapeCaves": true
}
```

Every key is optional and **a missing key means that zone is closed**. The file in the repo opens all
four. A misspelt key is logged as an unknown setting (`pvp.revenantCave`); a value that is not `true`
or `false` stops the server from starting, like the other settings.

## The zones (`pvp/PvpZones.kt`)

| Key | Where | Source of the bounds |
|---|---|---|
| `soulWarsArena` | the 6,037 tiles walkable from either team's graveyard portal (team barriers count as open, and the two bridges to the middle island are crossed), level 0 only | `pvp/soul_wars_arena.txt`, generated by `tools/dungeons/soulwars_arena.py`. The arena is ringed by a wall of map-edge forest (`snp_map_edge_forest_*` locs), so floor pockets behind it are outside. A first version used a bounding box (x 2119-2298, z 2881-2942) and wrongly included one, at 2264,2889. The lobby (z 2845-2855) is outside. |
| `revenantCaves` | `Dungeon.REVENANT_CAVES.areas` (x 3145-3270, z 10040-10240) | the dungeon definition |
| `wildernessBossLairs` | `WildLair.containing`: all six lairs (the three big ones and the three singles copies), arena plus the corridor to the exit | `WildernessLairs.kt` |
| `escapeCaves` | `EscapeCaves.area` (x 3328-3391, z 10240-10303) | `WildernessLairs.kt` |

The zones are plain rectangles in code. The one new symbol is the tick timer `pvp_zone_tick`
(`timer.sym` 33), so **run `./gradlew packCache` once** before starting the server (the sandbox copy
was packed this way for the tests).

## How it works

- **Rule (engine side):** `PvpRules` (api/combat/combat-scripts) holds rules and listeners that
  content registers. `PvPCombatScript.canAttack` asks it when a player clicks, and
  `PvPCombat.canAttack` asks it on every swing, so walking out of a zone or closing it ends a fight in
  progress. With no rules registered every attack is allowed.
- **Rule (isle side):** `PvpScript` registers one rule. Attacker and target must both stand in an
  open zone ("You can't attack other players here."), and two members of the same league team can
  never attack each other ("You can't attack your own teammates."). Players without a team can fight.
- **Attack option:** `LoginScript` sends player op 2 (Attack) as `null`. A repeating 1-tick soft timer
  (`pvp_zone_tick`, started at login) sends `Attack` (priority) when the player is in an open zone
  and `null` when they leave; it only sends when the state changes. It also catches teleports and
  deaths.
- **Skull:** `PvPCombat.markPk` (every attack path) tells the listeners; `PvpScript` (unless the attack is retaliation, below) calls
  `PvpSkull.refresh`. The skull is the white one (`skullicon_default`, the same as the amulet of
  avarice), lasts 2,000 ticks (20 minutes) from the latest attack, is not kept over a log out, and
  is cleared by death. `PvpSkull` and `AvariceScript` share the icon, so each one's expiry leaves
  the icon on while the other still holds it.
- **Shield specials:** `activateShieldSpecial` was `TODO()` and would have thrown on a player with the
  special bar on a shield. It now returns `false` (the swing is a normal attack); no shield special
  exists yet.

## Things to know

- **Revenant drops:** `DropVariantScript` treats any skull as "skulled", so attacking a player makes
  the next 20 minutes of revenant kills use the skulled drop tables. That is how the real game works.
- **Everywhere is multi-combat** (`combat_multiway_everywhere`), so there are no "already under
  attack" refusals between players.
- **Not built:** `::` admin commands for toggling a zone live (the file is read at startup), and
  hiding the Attack option on teammates (see below).

## Retaliation (`pvp/PvpFights.kt`)

Answering an attack is not skulled. A *fight* is the run of attacks between two players with no
pause longer than 100 ticks (one minute, a guess: the Wiki gives no window). Whoever attacks first
is the aggressor and is skulled, and each of their attacks refreshes the skull. The other player's
attacks in that fight are retaliation: no skull, however many. A fight that went quiet for more than
a minute starts again, and whoever attacks first is its new aggressor. Attacking a third player who
never attacked you is skulled as usual. A player who is already skulled keeps that skull as it was.

## The overlay (`pvp/PvpOverlay.kt`, `tools/cs2/`)

The client draws the Wilderness overlay (the `pvp_icons` interface: skull, "Level: N", combat level
range) from a Wilderness level that it works out itself, from the player's coordinates and the
Wilderness's regions written into the cache's `[proc,wilderness_level]` (clientscript 384). Nothing
the server sends can make it show elsewhere, so that proc is patched: six instructions added at the
start return the value of the new transmitted varp `isle_pvp_overlay` (65186, `varp.sym`) when it is
above 0, and the cache's own code runs unchanged otherwise. Script 384 is only called by the overlay's
own scripts (385/386 layout, 388 level text, 5224 combat range), so nothing else changes.

`PvpScript` sets the varp to 126 (the most, and its combat range, 3-126, covers every level) and runs
`[clientscript,combat_wilderness_transmit]` (390, which sets the client's "inside the Wilderness"
flag and redraws the overlay) when a player enters an open zone, and sets 0 and runs it with 0 on
leaving. `tools/cs2/patch_wilderness_level.py` rebuilds the patched script from the vanilla cache
(`tools/cs2/cs2lib.py` reads and writes compiled scripts and round-trips them byte for byte). The
sandbox cache was packed with it and script 384 in the served cache starts with the new block.

**The red circle on the skull.** The overlay's skull (`pvp_icons:46`, sprite 1046, a plain skull and
crossbones) has a red "no" circle (`pvp_icons:47`, sprite 1047) over it. In an ordinary world
`[proc,pvp_icons_layout]` (386) sets that circle opaque (`if_settrans 0`) every time it draws, and
only the Clan Wars FFA arena branch ever hides it, so the skull is shown "disabled" everywhere, in or
out of a PvP zone (it was already on screen outside the arena before the overlay patch). That proc is
patched as well (`tools/cs2/patch_pvp_icons_layout.py`): a seven-instruction block before its final
`return` sets the circle transparent (`if_settrans 255`) while `isle_pvp_overlay` is above 0. So the
plain skull means "PvP is on here" and the crossed one "off". Outside the zones the client still draws
it crossed, as it did before.

**Needs `./gradlew packCache`** (new varp definition and the scripts) and a client check: I could
not see the overlay draw. If it looks wrong, the one number to change is `PvpScript.OVERLAY_LEVEL`.

## Hiding the Attack option on teammates: not possible

The Attack option is one client-wide setting (`SetPlayerOp`), and the client decides what to show for
each player itself (`addPlayerToMenu`). The server cannot take Attack off one player's menu. The only
per-player thing the client does is to push Attack to the bottom of the menu for players on the same
*team*, and a player's team is read from a worn item: any of the 12 equipment slots whose item has a
non-zero `team` in the cache (the Castle Wars style team capes). The appearance the server sends can
show any item in a slot, so teams could be given by sending each player a team item, but it would
replace the cape or hood slot they have on, and Attack would still be there on the right-click
menu. So a teammate who is clicked is refused with "You can't attack your own teammates." as before.

## Client check for the user

1. Stand in each zone: right-click another player and "Attack" is there; step out and it is gone.
2. Attack a player on another team: a white skull appears over you, not over them.
3. Attack a teammate: "You can't attack your own teammates."
4. Die to a player: everything is kept, you respawn in the lobby graveyard, the skull is gone.
5. Set a zone to `false`, restart: no Attack option there.
